## 一、风格总结

### 1. 内容定位

文章不是单纯复述政策，而是把移民、身份、教育、资产配置等信息翻译成中国家庭能够理解的决策问题：

1. 发生了什么；
2. 哪些人会受到影响；
3. 对家庭规划意味着什么；
4. 是否需要调整原有方案；
5. 下一步应该核实什么、准备什么。

主要读者包括高净值家庭、企业主、家长、留学生家庭、跨境从业者，以及希望获得第二身份或提高全球通行能力的人群。

### 2. 标题风格

常见标题公式：

- 数字 + 核心结果 + 目标人群：`2年，一张美国绿卡和一个母亲的远见`
- 政策变化 + 实际影响：`加拿大7月迎来8项移民新规，看看你是否需要重新规划了`
- 条件反差 + 身份结果：`不买房、不创业，每年居住90天：……`
- 读者疑问 + 明确提醒：`如何轻松拿香港身份？五种方法+几个关键提醒`
- 场景或人物 + 戏剧性结果：`三天决定，三个月获批：一个父亲的香港速度`
- 旧认知挑战 + 新选择：`别再盯着葡萄牙！……`
- 风险提醒：`避坑丨这些流行的投资入籍项目，碰都不要碰`

标题可以有张力，但不能把预测写成官宣，不能虚构通过率、审批速度、收益、名额或截止时间。

### 3. 开头风格

主要有五种开头：

- 直接对话：`大家好，今天我们聊……`
- 问题切入：`你是否遇到过……`
- 个人经历或客户场景：先讲一个真实的人、决定或困境，再引出政策。
- 新闻钩子：从近期赛事、官方会议或一条政策消息切入，再转到身份规划问题。
- 反常识判断：先指出“大家以为……，但真正需要关注的是……”。

开头不做长篇背景铺垫，通常在前 2—4 段交代文章要解决的问题。语气偏口语，允许使用“简单说”“你这么算一笔账”“我个人觉得”等表达，但不能为了模仿口语而堆叠废话。

### 4. 正文结构

政策科普类常用：

```text
读者问题或政策背景
→ 用编号拆解申请路径/变化点
→ 每一点解释条件、适用对象和现实影响
→ 集中讲几个关键提醒
→ 总结适合谁、不适合谁
→ 咨询引导 + 风险声明
```

CEO 手记类常用：

```text
个人经历或反常识观点
→ 用生活细节建立可信度
→ 解释自己为什么形成这个判断
→ 分类型讨论行业现象或项目风险
→ 回到公司经营原则、合规或价值观
→ 留出下一篇话题或咨询入口
```

客户案例类应使用：

```text
真实人物的初始困境
→ 为什么原方案不合适
→ 决策过程和关键取舍
→ 办理节点与结果
→ 结果对家庭生活的真实影响
→ 哪类读者可以参考、哪些不能照搬
```

不得在没有真实案例材料时虚构姓名、职业、家庭成员、对话、办理周期或获批结果。

项目科普/转化类常用：

```text
读者的既有误区或现实焦虑
→ 项目的法案依据与核心条件
→ 3—5个具体使用场景
→ 办理或维护中的隐形门槛
→ 适合谁、不适合谁
→ 品牌服务如何解决具体难点
→ 咨询入口 + 风险声明
```

政策转方案类常用：

```text
一项已核验的政策变化
→ 解释政策背后的筛选逻辑
→ 指出旧方案增加了哪些不确定性
→ 提供一个或多个备选方向
→ 说明备选方案的适配条件和局限
→ 建议读者先评估，不制造恐慌成交
```

短讯类只适合已经核实、条件简单的单一项目，建议控制在 250—500 字。它不能替代完整政策解读，也不能承载复杂的税务、法律或教育结论。

### 5. 语言和节奏

- 第一人称和第二人称较多，像有经验的人面对面解释。
- 多用短段落和直白小标题；复杂政策拆成编号清单。
- 经常通过反问、对比和重复强调关键判断。
- 专业信息之后立刻翻译为客户影响，避免连续堆砌法规原文。
- 观点明确，但保留“个人判断”“需要根据实际情况核实”的边界。
- 品牌优势通常通过合规、经验、筛选标准和风险意识体现，而不是空喊“专业领先”。

从 25 篇全文看，两个公众号还有几种明显的语气差异：

- `环球出国`更偏信息编辑和 CEO 口述：解释性强、第一人称多、会用生活细节和自嘲建立信任。
- `环球移民`更偏市场转化：常用强问题、利益点编号、客户结果和行动窗口推动咨询。
- 生成时应保留这种差异，但统一提高事实严谨度；不能照搬样本中的夸张标题、未经证实预测或绝对结论。

### 6. 结尾和转化

标准结尾包含：

1. 一段总结或个人判断；
2. 给读者的下一步行动建议；
3. 自然的咨询引导；
4. 移民、法律、投资或税务风险声明。

咨询引导应与本文主题相关，避免正文刚讲完风险就突兀地强推项目。

### 7. 应学习与不应复制的部分

应学习：

- 把政策术语翻译成家庭决策、教育安排、企业经营或身份维护问题；
- 用一个核心问题贯穿全文，而不是堆很多互不相关的新闻；
- 用短段、小标题、对比和时间线降低阅读门槛；
- 案例中呈现“为什么选、怎么取舍、结果带来什么变化”；
- 品牌能力落在材料梳理、合规筛选、本地服务和长期维护等具体动作上。

不应复制：

- 把“将提交表决”写成“正式晋级”，或把媒体预测写成确定结果；
- 使用“确定性拉满、利好不存在变数、最优、零税负”等证据强度不足的绝对词；
- 没有一手来源就写房价涨幅、租金回报率、录取率、签证中签率或审批时间；
- 把“持有居留身份”和“成为税务居民”混为一谈；
- 为增强戏剧性而补造客户对话、心理活动、精确时间线或服务评价；
- 用个案获批速度暗示普遍办理周期；
- 先下结论再拼来源，或只引用行业媒体却写成官方结论。

## 二、推荐的生成方式

建议拆成两个调用：

1. **文章生成**：从日报中选择一个核心事件，生成公众号草稿和事实核对表。
2. **发布前审校**：检查事实、时间、适用人群、夸张措辞和文章结构。

不要让一次调用同时从几十条日报中硬拼出一篇文章。一篇文章聚焦一个核心事件；同一事件的多个来源可以合并佐证。

## 五、发布前审校 Prompt

```text
你是公众号发布前的事实核验与内容合规编辑。请审校下方文章，但不要直接重写全文。

依次检查：
1. 是否把旧闻、拟议、媒体预测写成今日已生效政策；
2. 日期、金额、收入、居住时间、审批周期、配额和资格条件是否有来源；
3. 是否虚构客户案例、对话、结果、通过率或投资收益；
4. 标题是否比正文证据更强；
5. 是否遗漏适用条件、限制或风险；
6. 是否把个案结论扩大为所有申请人；
7. 是否存在跨公众号重复事件、重复段落或同义反复；
8. 是否符合“场景切入—事实拆解—客户影响—行动建议—风险声明”的品牌结构；
9. 咨询引导是否自然，是否与正文主题一致；
10. 是否出现过度模仿参考文章的独特句子。

输出：

## 审校结论
{{可发布 | 修改后可发布 | 暂不可发布}}

## 必须修改
逐条列出问题、风险和建议改法。

## 建议优化
列出不影响事实但可改善标题、节奏、结构和转化的建议。

## 事实缺口
列出仍需业务人员或官方来源确认的内容。

## 推荐标题
在事实强度允许的范围内给出一个最终标题。

【待审文章】
{{draft_article}}

【核验来源】
{{verified_sources}}
```

## 六、接入现有项目的建议

生成输入可直接复用 `/api/market` 已有字段：

- `recommendedTitle`
- `angle`
- `customerImpact`
- `riskNote`
- `projectName`
- `publishedAt`
- `link`

但这些字段目前主要由规则生成，只适合作为选题输入，不能替代官方事实来源。正式生成前应补充 `verified_sources`，生成后再执行一次“发布前审校 Prompt”。

## 七、建议的每日自动化流程

当前测试证明这套方案可实现，但生产流程不应依赖每天人工用 Chrome 打开几十篇文章。更稳妥的链路是：

```text
定时刷新 WeRSS
→ 拉取两个 JSON feed
→ 检查 content 是否已回填
→ HTML 转纯文本并清除微信播放器/UI噪声
→ 按原文链接、标题语义和核心事件三层去重
→ 日报选出 1—3 个候选事件
→ 补充政府/主管部门原始来源
→ 运行文章生成 Prompt
→ 运行发布前审校 Prompt
→ 人工确认事实、品牌信息和咨询入口
→ 进入公众号编辑器
```

建议为每条素材增加以下状态字段：

- `contentStatus`: `full | summary_only | missing`；
- `sourceLevel`: `A | B | C | D`；
- `policyStatus`: `effective | announced | pending | proposed | media_report | opinion`；
- `eventKey`: 用于跨公众号和跨来源去重；
- `verifiedAt`: 最后核验时间；
- `manualReviewRequired`: 是否必须人工确认。

自动化的硬门槛：

1. `summary_only` 或 `missing` 的文章可以参与选题，不得直接作为完整事实依据；
2. 没有A级来源时，不输出“可发布稿”，只输出选题草案和待核实清单；
3. 客户案例必须关联经过授权的案例材料，不允许模型自行补齐故事；
4. 生成与审校使用两个独立调用，审校时必须同时传入原始来源；
5. 最终发布保留人工确认，尤其核对标题、政策状态、数字、税务和投资表述。

本次实测还发现，WeRSS 的正文可能在刷新或访问原文后异步回填：同一 feed 早期可见空 `content`，稍后已有正文。因此抓取任务应设计重试机制，例如首次为空时标记 `pending`，间隔一段时间再次刷新；浏览器只作为异常素材的人工补抓工具，不作为日常批处理主链路。
