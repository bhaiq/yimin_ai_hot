# H 专栏：Henry 内容工作台 PRD

> 文档状态：P0 已实现，待部署验收  
> 版本：v0.3  
> 日期：2026-07-24  
> 内容方法：Henry 文章与视频写作 Skill  
> 默认生成模型：DeepSeek v4-pro（模型可替换）  
> 产品范围：移民热点系统内的 Henry 选题、事实包、草稿与审校工作台

## 1. 一句话定义

H 专栏不是“另一个自动日报”，而是一个把日报事件转化为 Henry 可判断、可成稿、可审阅内容的工作台。

系统负责减少 Henry 阅读、整理和起草的时间；Henry 或编辑负责确认真实判断、第一人称经历、事实风险和最终发布。

## 2. 第一性原理

### 2.1 用户真正需要的不是更多文字

AI 生成文字的成本已经很低。H 内容真正稀缺的是：

1. Henry 的注意力；
2. Henry 对一件事的真实判断；
3. 足以支持判断的可靠事实；
4. 读者能够理解和使用的选择逻辑；
5. Henry 本人和品牌长期积累的信任。

因此，产品不能以“每天自动生成多少篇文章”为第一目标。大量未经选择的草稿只会把日报的信息噪声变成新的草稿噪声。

### 2.2 一篇 H 内容成立的最小条件

一篇内容只有同时回答下面四个问题，才值得进入完整初稿：

1. **有观点吗？** 除了复述新闻，Henry 真正想表达什么选择逻辑？
2. **有依据吗？** 是否存在完整原文、官方来源、已确认经历或可追溯数据？
3. **对读者有用吗？** 能否帮助读者缩小选择范围、识别风险或采取行动？
4. **能回到长期价值吗？** 能否自然回到专业、合规、安全、公平、全球化或长期主义？

四项全部成立，允许生成完整初稿。

只有两到三项成立，只生成选题角度、大纲和事实缺口。

只有零到一项成立，系统明确显示“暂不建议成稿”，不为了维持日产量而硬写。

### 2.3 人机边界

AI 可以：

- 从日报中发现候选事件；
- 合并重复报道；
- 整理全文、官方来源和反方证据；
- 生成选题、标题、大纲和渠道建议；
- 按已确认观点扩写文章或口播；
- 做事实、结构、口吻和原创性审校；
- 把同一事实包改写成不同渠道版本。

必须由 Henry 或编辑确认：

- Henry 本次对事件的核心立场；
- 第一手经历、真实情绪、对话和现场细节；
- 客户案例、公司数字和业务事实；
- 强第一人称判断；
- 法律、税务、投资、品牌合规和最终发布。

### 2.4 产品优化目标

优先优化：

- Henry 从打开页面到完成一次选题判断的时间；
- 候选题的有效率；
- 初稿进入本人审阅的比例；
- 事实缺口被系统提前发现的比例；
- 从文章复用为视频内容的效率。

不优先优化：

- 每日生成文章数量；
- AI 输出字数；
- 模仿口头禅的相似度；
- 未经审阅的一键发布速度。

## 3. 背景与现状

当前系统已经具备：

- RSS、网站等信源抓取；
- 文章入库、翻译和基础分类；
- 文章级相关性、重要度和中文摘要分析；
- 同一事件聚合；
- 今日新增、重要变化、延续关注和不建议重复分组；
- 日报、市场素材、历史记录和反馈；
- DeepSeek OpenAI 兼容调用；
- 企业微信身份和管理员登录；
- 原生 Node.js、MySQL 和单页应用。

当前系统尚不具备：

- 面向 Henry 的独立内容工作流；
- 原文全文与 `full / summary_only / missing` 状态；
- 来源等级、政策状态和核验时间；
- Henry 本次观点输入；
- “选题—观点—初稿—审校—本人确认”的状态流转；
- 公众号和视频脚本的统一事实包；
- H 内容版本、审校结果和采用反馈；
- 适配 Henry 文章与视频写作 Skill 的任务模式。

现有 `yimin_articles.summary` 多数是短摘要。日报又经过一次 AI 压缩，因此日报内容可以用于发现选题，不能默认作为 2500—3800 字文章的完整事实依据。

## 4. 产品目标

### 4.1 核心目标

每天公共日报完成后，定时任务可以请求系统生成 0—3 个 H 候选题，并提前生成默认候选的可编辑文章。Henry 打开 H 专栏即可：

1. 快速理解候选事件；
2. 看见系统推荐的 H 角度、受众和渠道；
3. 看见事实是否充分、还缺什么；
4. 认可、修改或拒绝系统建议；
5. 输入一句真实判断；
6. 生成公众号文章或视频口播；
7. 查看独立审校结果；
8. 复制、导出或交给编辑继续处理。

### 4.2 成功标准

第一期上线后应能够验证：

- 每个有内容的日报日自动产生不超过 3 个去重候选，并可提前生成默认文章草稿；
- 不值得写的日期允许产生 0 个候选；
- Henry 在手机端可以在 3 分钟内完成一个候选的“采用 / 不采用 / 补充观点”判断；
- 所有完整初稿都有明确事实包和独立审校结果；
- 缺少核心证据或本人判断的内容不会被标成“可进入本人审阅”；
- 同一选题可以在不重建事实的情况下生成文章或视频版本；
- 所有生成结果可追溯到模型、Skill 版本、人物档案版本和输入事实快照。

## 5. 非目标

第一期不做：

- 自动发布到公众号、视频号、抖音、YouTube；
- 无人审核的第一人称发布稿；
- Henry 人格克隆；
- 自动虚构经历、客户案例或公司故事；
- 每日强制生成固定篇数；
- Claude、Gemini API 的直接集成；
- 复杂多人审批流；
- 自动剪辑视频、生成数字人或克隆声音；
- 用历史文章做贴近改写。

## 6. 用户与权限

### 6.1 H 专栏成员

以下身份可以看到并进入 H 专栏：

- Henry；
- Celine（梁爽）；
- 企业微信通讯录中直属部门为 IOD 部门的成员；
- 系统管理员。

以上成员采用完全相同的权限，可以查看和选择候选、补充与核验来源、确认观点、编辑与审校草稿、退回修改以及最终采用。

### 6.2 权限原则

- 页面和 API 不公开；
- 能看到 H 菜单就拥有 H 专栏全部权限，不再细分内部角色；
- Henry 和 Celine 使用身份白名单，IOD 成员使用同步后的企业微信直属部门判定，系统管理员使用后台登录态；
- 其他人员看不到菜单，且 `/api/h/*` 返回 `403`；
- 所有写操作记录真实操作者 UserID 和时间。

## 7. 具体使用场景

### 场景一：Henry 每天打开系统，只看值得判断的 0—3 个题

**触发条件**

当天公共日报已生成，系统完成事件聚合。

**用户路径**

1. Henry 从导航进入“H 专栏”；
2. 默认看到“今日候选”，已由定时任务处理的选题同时带有可编辑文章；
3. 页面显示 0—3 张候选卡，而不是完整日报；
4. 每张卡在首屏回答：
   - 发生了什么；
   - 为什么可能值得 Henry 说；
   - 推荐受众；
   - 推荐主渠道；
   - 事实是否充分；
   - 需要 Henry 确认什么；
5. Henry 选择“值得写”“以后再说”或“不写”。

**成功结果**

Henry 不需要阅读几十条日报，也不需要先读 AI 长文，就能完成内容判断。

**异常结果**

当天没有符合条件的题目时，页面显示：

> 今天没有足够值得 Henry 专门成稿的题目。系统没有为了凑数量生成内容。

### 场景二：政策事件有价值，但系统缺少 Henry 的真实判断

**示例**

日报发现一项投资移民拟议规则。系统已找到完整原文和主管部门文件，但无法知道 Henry 最想提醒客户什么。

**用户路径**

1. 候选卡状态为“待 Henry 观点”；
2. 系统展示已确认事实和建议角度；
3. 系统最多提出三个高价值问题：
   - 你对这件事真正想表达的观点是什么？
   - 你最担心客户误解哪一点？
   - 有没有可以公开使用的本人经历或公司事实？
4. Henry 输入一句或一段话；
5. 系统保存为“本次已确认观点”；
6. 生成完整文章或口播。

**成功结果**

系统负责扩写 Henry 的判断，而不是替 Henry 发明判断。

### 场景三：只有行业媒体摘要，证据不足

**示例**

某行业媒体称一个新项目“前景独特”，但系统只有标题和摘要，没有主管部门原文。

**用户路径**

1. 候选卡显示：
   - 内容状态：`summary_only`；
   - 来源等级：C；
   - 政策状态：`opinion` 或 `media_report`；
2. 系统允许输出“选题卡”和“事实缺口”；
3. “生成完整 H 稿”按钮不可直接进入可审状态；
4. 编辑可以补充官方来源或完整原文；
5. 证据补齐后重新评估。

**成功结果**

系统不会把行业观点扩写成确定政策，也不会把摘要假装成完整原文。

### 场景四：Henry 的稳定观点可以直接支持选题

**示例**

日报或内部公开材料出现“AI 是否会替代专业顾问”的讨论。该主题与人物档案中已确认的“AI 是装备，不是专业替代品”一致。

**用户路径**

1. 系统标明判断来源为“已确认人物档案”；
2. 展示可使用范围和不可外推边界；
3. 自动生成选题、大纲或供本人审阅的初稿；
4. 不虚构新的会议、客户、旅行或个人经历；
5. Henry 仍需终审第一人称成稿。

**成功结果**

减少对稳定观点的重复追问，同时不借稳定观点发明新故事。

### 场景五：同一个事实包生成不同渠道版本

**用户路径**

1. 选题已经有内容大纲、当前事实包和可用的已确认观点；
2. Henry 或编辑点击“一键生成整套稿件”；
3. 系统并行生成四个独立版本：
   - 公众号文章；
   - H快评：60—120 秒；
   - H边跑边聊：5—8 分钟；
   - H深聊：8—12 分钟；
4. 四个版本分别从所选大纲组织渠道结构和标题，不以公众号文章机械删短生成视频；
5. 数字、政策状态、适用条件和风险继续引用同一事实包；
6. 页面显示 0/4—4/4 生成进度；部分失败时保留成功版本，并允许单独重试失败渠道；
7. 四个渠道版本分别审校渠道节奏和发布风险。

**成功结果**

同一选题只维护一套事实，文章和视频保留不同表达结构。

### 场景六：编辑完成修订，交给 Henry 最终看

**用户路径**

1. 编辑补充来源并修改草稿；
2. 系统保存新版本，不覆盖旧稿；
3. 编辑运行发布前审校；
4. 系统输出：
   - 可进入本人审阅；
   - 补充事实后审阅；
   - 暂不建议成稿；
5. Henry 查看正文和“必须确认”事项；
6. Henry 标记“本人已看”“采用”或“退回修改”。

**成功结果**

Henry 看见的是接近决策的信息，而不是模型的隐藏过程或一大段泛泛说明。

### 场景七：使用外部 Claude 或 Gemini 继续创作

第一期不直接接入外部模型 API，但允许导出“本次内容包”，包括：

- 选题和核心问题；
- 目标受众；
- 完整事实包；
- 来源等级和政策状态；
- Henry 本次已确认观点；
- 人物档案可用边界；
- 禁止事项；
- 推荐任务模式；
- 当前草稿；
- 期望输出格式。

外部模型生成的版本可以由编辑复制回系统并标记模型来源。系统仍是事实包、版本和反馈的唯一记录处。

## 8. 信息架构

### 8.1 导航

在现有主导航增加：

- **H 专栏**

建议位置：

- “移民日报”之后；
- “市场素材”之前。

### 8.2 H 专栏一级页面

包含四个页签：

1. **今日候选**
2. **草稿库**
3. **待我确认**
4. **历史**

### 8.3 今日候选

顶部信息：

- 当前日期；
- 今日候选数量；
- 待 Henry 观点数量；
- 可进入初稿数量；
- 暂不建议成稿数量；
- 最近生成时间；
- 手动刷新按钮。

候选卡字段：

- 选题标题；
- 事件摘要；
- 一句话核心问题；
- 推荐 Henry 角度；
- 目标读者；
- 推荐主内容模式；
- 可复用内容模式；
- 来源数量；
- 最高来源等级；
- 内容完整度；
- 政策状态；
- H 选题四问结果；
- 当前缺口；
- 与近 30 天内容的重复风险；
- 状态。

候选卡操作：

- 值得写；
- 以后再说；
- 不写；
- 查看事实；
- 补一句我的判断；
- 生成内容大纲；
- 选择任一历史大纲后生成整套渠道稿；事实或观点缺口留给后续四层审校处理。

### 8.4 选题详情

页面分为三个逻辑区域，移动端按顺序纵向排列。

#### A. 事实包

- 事件时间线；
- 原始日报事件；
- 关联来源；
- 来源等级；
- 原文完整度；
- 政策状态；
- 已核验事实；
- 待核验事实；
- 反方信息或限制；
- 来源链接和核验时间。

#### B. Henry 观点

- 系统建议核心角度；
- 已确认人物档案中可用观点；
- 不可外推边界；
- Henry 本次输入；
- 编辑整理版本；
- 观点确认人和确认时间；
- 最多三个待回答问题。

#### C. 内容产出

- 位于事实包、Henry 观点和大纲/稿件编辑之后，作为页面最后一步；
- 推荐内容模式；
- 标题强度；
- 生成或更新内容大纲；
- 一键生成公众号文章、H快评、H边跑边聊和 H深聊；
- 单独生成或重试某个渠道；
- 查看四渠道各自的版本与审校状态；
- 当前版本；
- 待确认事实；
- 审校结果；
- 复制和导出。

### 8.5 草稿详情

显示：

- 标题候选；
- 推荐标题及理由；
- 文章大纲或视频定位；
- 正文或口播稿；
- 摘要、配图、画面和字幕建议；
- 待确认事实；
- 核验提示；
- 四层质检结果；
- 模型、Skill 版本、人物档案版本；
- 输入事实快照；
- 版本历史；
- 编辑区；
- 复制 Markdown；
- 复制纯文本；
- 导出内容包。

### 8.6 待我确认

只显示需要 Henry 处理的事项：

- 待确认核心观点；
- 待确认第一人称经历；
- 待确认公司事实；
- 待本人审阅初稿；
- 编辑退回的问题；
- 已超过设定时间未处理的内容。

不把普通系统错误、抓取日志和低价值后台信息放给 Henry。

## 9. 内容模式

系统使用 Henry 文章与视频写作 Skill 的任务模式：

| 模式 | 产品名称 | 默认用途 |
|---|---|---|
| `topic` | 选题卡 | 角度、受众、价值、风险 |
| `titles` | 标题方案 | 默认 8 个标题 |
| `outline` | 内容大纲 | 主轴、事实边界、核心观点、论点、风险和行动 |
| `wechat_article` | 公众号文章 | 默认 2500—3800 字 |
| `short_video` | H快评 | 60—120 秒 |
| `run_and_talk_video` | H边跑边聊 | 5—8 分钟，默认视频模式 |
| `deep_video` | H深聊 | 8—12 分钟 |
| `spoken_rewrite` | 口述整理 | 整理 Henry 的原始口述 |
| `review` | 发布前审校 | 四层质检 |

用户未指定渠道时：

- 先生成并选择一个内容大纲；
- 用户点击“一键生成整套稿件”后并行生成四个渠道；
- 用户也可以选择只生成一个渠道。

## 10. 状态设计

### 10.1 选题状态

| 状态 | 含义 |
|---|---|
| `candidate` | 系统生成的候选 |
| `selected` | Henry 或编辑选择值得写 |
| `later` | 暂缓 |
| `rejected` | 不写 |
| `archived` | 历史归档 |

### 10.2 成稿准备度

| 状态 | 含义 |
|---|---|
| `not_recommended` | H 四问只有 0—1 项成立 |
| `topic_only` | 可看角度，但事实或观点不足 |
| `outline_ready` | 可生成内容大纲和事实缺口 |
| `needs_viewpoint` | 事实基本充分，缺 Henry 观点 |
| `needs_evidence` | 有角度和观点，缺核心证据 |
| `draft_ready` | 事实与观点满足初稿门槛 |

### 10.3 草稿状态

| 状态 | 含义 |
|---|---|
| `generating` | 正在生成 |
| `drafted` | 已生成，未审校 |
| `reviewing` | 正在审校 |
| `needs_revision` | 必须修改或补事实 |
| `ready_for_henry` | 可进入本人审阅 |
| `henry_reviewed` | Henry 已看 |
| `approved` | Henry 或授权编辑确认采用 |
| `rejected` | 放弃该版本 |
| `failed` | 生成失败，可重试 |

### 10.4 发布准备度

严格使用 Henry 内容四层质检的三个结果：

- `可进入本人审阅`
- `补充事实后审阅`
- `暂不建议成稿`

系统第一期不使用“AI 判断可直接发布”这一状态。

## 11. 事实与发布门槛

### 11.1 内容完整度

每个来源必须标记：

- `full`：有足够完整的原文；
- `summary_only`：只有标题或摘要；
- `missing`：正文和有效摘要均缺失。

`summary_only` 和 `missing` 可以参与选题，不得作为完整政策事实依据。

### 11.2 来源等级

| 等级 | 定义 |
|---|---|
| A | 政府、议会、移民局、税务机关、法院、官方公报或法案原文 |
| B | 能直接采访主管机关或提供原始文件链接的权威媒体 |
| C | 行业媒体、律所、机构解读 |
| D | 社交媒体、市场传闻、未核验口述 |

### 11.3 政策状态

- `effective`：已生效；
- `announced`：已公布，待生效；
- `pending`：流程进行中；
- `proposed`：拟议；
- `media_report`：媒体报道；
- `opinion`：观点或分析；
- `not_applicable`：非政策题。

### 11.4 政策、法律、税务和投资题门槛

核心确定性事实原则上必须有 A 级来源。

没有 A 级来源时：

- 可以生成选题卡；
- 可以生成事实缺口和待核验问题；
- 可以在明确降级表述的情况下生成内部内容大纲；
- 不得标记为“可进入本人审阅”的完整发布型初稿。

### 11.5 Henry 观点门槛

强第一人称内容的判断来源必须属于：

- 已确认人物档案；
- Henry 本次明确输入；
- 可核实公开材料中 Henry 已表达的观点。

系统建议角度不等于 Henry 已确认观点。

### 11.6 经历和公司事实门槛

- 个人经历只能使用已确认范围；
- 不补写时间、地点、人物、对话、感受和结果；
- 公司数字必须有授权口径和统计时间；
- 缺统计日期的公司数字只进入待确认事实；
- 客户案例、家庭隐私、内部会议、人事信息和未公开规划不得进入生成输入。

## 12. AI 工作流

### 12.1 阶段一：候选生成

输入：

- 当日公共日报事件；
- 关联文章快照；
- 近 7 天日报使用记录；
- 近 30 天 H 内容记录；
- 已确认人物档案；
- 候选生成规则。

输出结构化 JSON：

- 候选标题；
- 核心事件；
- 目标读者；
- 推荐内容原型；
- 推荐主模式；
- 可复用模式；
- 建议核心角度；
- H 四问结果及可验证理由；
- 事实缺口；
- 需要 Henry 回答的问题；
- 不成稿理由；
- 近 30 天重复风险。

规则：

- 默认最多 3 个候选；
- 允许 0 个；
- 同一事件不因多个链接重复入选；
- 近 7 天无实质进展的事件不能包装为今日新选题；
- 候选排序可以使用综合分，但能否成稿必须由硬门槛决定，不能只看分数。

### 12.2 阶段二：事实包建立

系统只对入选候选尝试抓取全文，避免为全部日报文章增加成本。

处理顺序：

1. 读取现有 RSS 原文内容；
2. 尝试复用现有 Firecrawl 或 Jina 抽取能力；
3. 清理导航、播放器和页面控件噪声；
4. 标记正文完整度；
5. 查找或由编辑补充官方来源；
6. 提取可证明事实；
7. 标记来源等级、政策状态和核验时间；
8. 保留原始文本或内容哈希用于追溯。

自动抓取失败时允许编辑：

- 粘贴原文；
- 增加来源链接；
- 手动设置来源等级和政策状态；
- 标记某条事实已人工核验。

### 12.3 阶段三：观点确认

系统根据事实包和人物档案判断：

- 是否已有稳定观点可用；
- 是否需要 Henry 补充本次观点；
- 是否需要经历或情绪节点；
- 是否涉及禁区。

最多向 Henry 展示三个问题。

第一期支持文本输入。

语音录制、上传和转写作为 P1，不作为 P0 上线阻塞项。

### 12.4 阶段四：初稿生成

初稿生成必须传入：

- 明确任务模式；
- 唯一核心结论；
- 目标读者；
- 事实包；
- Henry 已确认观点；
- 可使用人物事实；
- 待确认事实；
- 禁止事项；
- 渠道规则；
- 输出格式；
- Skill 和人物档案版本。

公众号和视频分别使用对应渠道规则，不使用一个万能 Prompt。

### 12.5 阶段五：独立审校

生成与审校必须是两个独立调用。

审校输入包括：

- 完整草稿；
- 原始事实包；
- Henry 观点；
- 人物档案边界；
- 近 30 天内容；
- 四层质检规则。

审校输出：

- 总体结论；
- L1 事实与风险；
- L2 判断与结构；
- L3 H 口吻与渠道；
- L4 原创性与发布准备；
- 待确认事实；
- 发布前必须处理；
- 可验证的问题位置。

审校不能输出隐藏思维过程，只输出问题、证据和修改结果。

## 13. 模型策略

### 13.1 第一版默认

- 候选生成：DeepSeek v4-pro；
- 初稿生成：DeepSeek v4-pro；
- 独立审校：DeepSeek v4-pro 的独立调用；
- 不要求第一版接入第二家模型。

### 13.2 模型中立

虽然第一版使用 DeepSeek，产品数据结构和调用层不得把“H 专栏”写死为 DeepSeek。

调用层应接受：

- provider；
- model；
- task mode；
- system prompt；
- temperature；
- prompt version；
- input snapshot；
- timeout；
- structured output expectation。

未来可以为不同阶段配置 Claude、Gemini 或其他兼容模型，而不修改业务数据结构。

### 13.3 可追溯性

每次生成保存：

- 模型名称；
- 任务模式；
- Skill 版本；
- 人物档案版本；
- Prompt 版本；
- 输入哈希；
- 事实包快照；
- 生成时间；
- 错误信息；
- 操作者或触发来源。

不保存或展示模型隐藏推理。

## 14. 功能优先级

优先级含义：

- **P0**：第一版上线必须具备的核心闭环，缺少其中任一关键环节就不能完成产品目标；
- **P1**：P0 稳定后增加，能够明显提高效率或体验，但不阻塞第一版使用；
- **P2**：后续根据实际使用反馈评估的增强能力。

### 14.2 P1：第一期稳定后

- 浏览器内语音录制；
- 音频上传和转写；
- 企业微信向 Henry 推送“今日候选”卡片；

### 14.3 P2：后续评估

## 17. 自动触发与幂等

### 17.1 自动触发

推荐顺序：

1. 公共日报生成完成；
2. 部门日报不阻塞 H 候选；
3. 定时任务通过公开接口生成 H 候选；
4. 对默认候选尝试补全文、生成大纲和四个可编辑渠道稿；单渠道失败自动重试且不回滚其他成功稿；
5. H 专栏显示预生成结果，人工继续编辑、审校和采用。

如果定时任务没有触发：

- Henry 首次打开当日页面时，系统可以启动一次后台补生成；
- 页面显示“正在准备今日候选”；
- 同一日期不得重复启动多个任务。

### 17.2 幂等键

候选生成建议包含：

- 日期；
- 公共日报输入哈希；
- 候选规则版本；
- Skill 版本；
- 人物档案版本。

草稿生成建议包含：

- topic id；
- mode；
- 事实包哈希；
- 已确认观点哈希；
- Prompt 版本；
- Skill 版本；
- 人物档案版本。

相同输入重复点击时优先返回已有结果；用户明确选择“重新生成”时创建新版本。

## 19. UI 与交互要求

### 19.1 Henry 优先

- 首屏先显示“值不值得写”，不先显示长篇 AI 分析；
- 主要操作在手机单手可点击范围内；
- 每张卡最多一个主按钮；
- 事实风险使用明确文字，不只用颜色；
- 不展示模型隐藏推理；
- 系统问题最多三个；
- 所有等待状态可退出页面，后台继续；
- 失败时保留输入，不让 Henry 重说观点。

### 19.2 可信度表达

页面必须明确区分：

- 系统建议；
- Henry 已确认；
- 编辑已核验；
- 官方来源事实；
- 媒体观点；
- 待确认内容。

禁止使用含混的“AI 已验证”“AI 可发布”等标签。

### 19.3 空状态

需要设计：

- 今天没有合适选题；
- 日报尚未生成；
- 候选正在生成；
- 候选生成失败；
- 事实不足；
- 尚无 Henry 观点；
- 尚无草稿；
- 审校未通过；
- 历史无记录。

## 20. 指标

### 20.1 核心指标

- 候选采用率；
- 候选进入初稿率；
- 初稿进入本人审阅率；
- 本人最终采用率；
- 从打开候选到完成判断的中位时间；
- 每篇采用内容的人工修改时间；
- 事实缺口在初稿前发现率；
- 同一事实包的跨渠道复用率。

### 20.2 质量指标

- 虚构经历事故数：目标 0；
- 未标记政策状态事故数：目标 0；
- 摘要被误当全文事故数：目标 0；
- 未经确认进入第一人称的强观点数：目标 0；
- 近 30 天重复选题漏检率；
- 审校后仍需因事实问题整篇退回的比例。

### 20.3 不作为成功指标

- AI 每日产稿数量；
- 平均字数；
- 页面停留时间；
- 单纯的标题刺激度。

## 21. 风险与处理

### 风险一：每天硬凑内容

处理：

- 允许 0 个候选；
- 显示“不建议成稿”的原因；
- 不设置日产量 KPI。

### 风险二：日报摘要的信息损失被继续放大

处理：

- 日报只用于发现选题；
- 入选后自动补全文，只为未抓取成功的来源保留重试入口；
- 没有全文则标记 `summary_only`；
- 高风险内容必须有 A 级来源。

### 风险三：模型把建议角度写成 Henry 本人观点

处理：

- 观点来源结构化；
- 系统建议与已确认观点分开展示；
- 强第一人称判断只能来自已确认观点；缺少已确认观点时可以生成渠道结构和中性表达，但不得冒充 Henry 本人判断，且最终采用由审校阻断。

### 风险四：模型虚构经历和公司事实

处理：

- 使用版本化人物档案；
- 禁区不进入模型输入中的可用事实区；
- 生成后执行 L1 和 L4 审校；
- 缺口使用占位符，不自动补齐。

### 风险五：DeepSeek 长文质量不稳定

处理：

- 候选、初稿、审校分开；
- 保存输入和版本；
- 模型调用层保持可替换；
- 第一版通过真实选题记录人工修改时间；
- 不因未来可能换模型而推迟工作流建设。

### 风险六：Henry 被过多问题打断

处理：

- 只在无法从人物档案和事实包判断时提问；
- 一次最多三个问题；
- 支持一句话输入；
- P1 增加语音。

### 风险七：外部 AI 导致版本散落

处理：

- 系统导出标准内容包；
- 外部结果可回存；
- 系统始终保存唯一事实包和最终采用版本。

## 23. P0 验收标准

### 候选

- 给定已生成公共日报，当日可生成 0—3 个 H 候选；
- 重复执行不会产生重复候选；
- 每个候选显示 H 四问、事实状态和推荐模式；
- 近 7 天旧事件不会被包装为今日新增；
- 近 30 天 H 内容重复风险可见；
- Henry 可以采用、暂缓或拒绝。

### 事实

- 每个来源都有内容完整度；
- 政策类来源有来源等级和政策状态；
- `summary_only` 不会被显示为完整原文；
- 无 A 级核心证据的高风险题不能进入“可进入本人审阅”；
- 编辑可以补充和更新来源。

### 观点

- 系统建议与 Henry 已确认观点明确分开；
- Henry 可以输入、确认、编辑和删除历史观点；
- 未确认的强第一人称观点不会进入可审状态；
- 人物档案禁区不会出现在生成结果中。

### 草稿

- 至少支持公众号、H快评、H边跑边聊、H深聊；
- 每次生成创建可追溯版本；
- 草稿包含待确认事实和核验提示；
- 可以复制 Markdown 和纯文本；
- 同一事实包可以生成不同模式。

### 审校

- 初稿和审校是独立调用；
- 审校输出 L1—L4；
- 输出三个标准发布准备度之一；
- 有必须修改项时不能标记 `ready_for_henry`；
- Henry 可以标记已看、采用或退回。

### 权限与稳定性

- 未授权用户不能访问 H 专栏 API；
- 所有写操作记录操作者；
- 观点确认和最终采用日志能够区分本人操作与授权代操作；
- 模型超时不丢失 Henry 已输入内容；
- 生成任务可以安全重试；
- 手机端可以完成核心流程；
- 不影响现有日报、市场素材和推送功能。
